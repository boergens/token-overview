A SMALL GUIDE

An honest overview.

Chat subscriptions are read live where a source exists; everything else can be recorded by hand. Developer APIs show read-only OpenAI and Anthropic reporting once connected.

Where the live numbers come from

  1. Claude: the collector uses the Claude Code sign-in on the owner’s machine to call Anthropic’s usage endpoint, the same one Claude Code shows with /usage. It reports the 5-hour window, the weekly window and, where they apply, model-specific weekly limits such as the separate weekly limit for Fable on Max and Ultra plans, each as a percentage used with a reset time, plus how this week’s use splits across Claude Code, chats and Cowork. Chats and Claude Code share all of these limits.
  2. ChatGPT: the collector uses the Codex sign-in to call ChatGPT’s usage endpoint, the one Codex shows with /status. It reports the plan’s Codex rate-limit windows as a percentage used with a reset time, and per model (for example GPT-6 Astra) only whether it can be used now and, if it is blocked, when it reopens; there is no percentage for those. A blocked model shows as blocked, with its reopen time, and that applies only to that model.
  3. Gemini: the collector runs the agy CLI (Google Antigravity, signed in with the owner’s Google account) in print mode with its /usage command, which lists the plan’s remaining quota for Gemini models and, separately, for the Claude and GPT models Antigravity offers, each with a 5-hour and a weekly window. This is the Google AI plan’s Antigravity quota, not the Gemini app’s own message limits.

Provider screens usually count up and this page counts down, so cards show both: “% left” is 100 minus the provider’s own “% used” figure for that window. Nothing is estimated, and the windows are the providers’ windows, not a token count. Each card’s gauge shows the most limiting window (a used-up weekly limit beats a fresh 5-hour window), and every window is listed underneath with its own reset time. A model-specific limit such as Fable’s blocks only that model, so a smaller gauge underneath shows what is left for the model you would switch to. For Claude that is Opus 5.5, which has no limit of its own and counts against the weekly all-models limit.

Freshness

The collector runs every five minutes and the page refreshes itself at the same cadence. If the feed is older than 15 minutes the cards say so. If a sign-in on the collector machine expires, the card explains it; opening Claude Code, Codex or agy once refreshes that token.

Manual readings

For a provider or window without a live figure, add what the account shows: a percentage or an exact unit. Readings older than an hour are labeled as old, and once a recorded reset time passes the card asks for a new reading. A live figure always takes precedence over a manual one for the same window.

Forecast

Every collector run is kept as history. Each card’s forecast replays blocks of your own past usage, favoring recent days, a similar time of day and a similar busy or idle state, then applies each window’s real rules until something reaches 100%. Counting how often each window gets there first gives the odds. They are rough: in a backtest it was no better than “same pace as the last 7 days” at predicting the next day, and it can’t foresee a sudden burst.

Credits

The Credits & APIs tab lists each pot separately: usage credits that extend a chat plan, API credits your plan includes each month, and purchased balances. These don’t mix. For example, Claude’s monthly API credits don’t cover Claude Code. A row marked “Checked” was read by hand on the date shown; you can record a newer balance with its button, which stays in this browser.

API usage and budgets

Connected API reports show consumed tokens for this calendar month in UTC, with a displayed scope and retrieval time. Reporting can be delayed. OpenAI covers its completions usage report; Anthropic covers its Messages API. A personal token budget is your tracking target for that scope, not a provider quota, prepaid balance, or spending control. Cached input is counted once. Dollar balances are never converted into token estimates.

What stays where.

Manual readings and budgets live in this browser only; export a backup before clearing browser data. The live feed holds percentages, reset times and plan names, nothing else. Sign-in tokens never leave the collector machine, and API reporting credentials stay on the server.

Private when deployed.

Cloudflare Access and a verified owner email are required before any page, asset, or report is served. A local preview is labeled separately.

Personal token budget

Set your own monthly tracking target for the scope shown on the API card. This does not change the provider’s quota or enforce a spending limit.

Remaining = your budget minus provider-reported input and output tokens. It stays unknown until usage is connected.

Connect API reporting

The dashboard reads reporting data only. It never makes model requests.

OpenAI API

Configure an OpenAI admin reporting credential as the server secret OPENAI_ADMIN_KEY. Optionally set OPENAI_PROJECT_ID to restrict the report to one project.

Anthropic API

Anthropic’s Admin API is not available to individual accounts, which is what the Console organization here is, so this report stays off unless you set up an organization in the Console. Then configure an admin credential as ANTHROPIC_ADMIN_KEY, and optionally ANTHROPIC_WORKSPACE_ID to restrict the report to one workspace.

Gemini API

Automatic reporting is not configured. Use the quota or billing screen in Google AI Studio or Vertex AI to record your balance. The source must match the service you use.

Add credentials through Cloudflare’s Variables and Secrets settings for this private site, then redeploy. Do not paste them into chat or into balance fields.

Once connected, open Developer APIs or select Refresh usage. Reports may be cached for up to one minute and providers may report usage with a delay.
